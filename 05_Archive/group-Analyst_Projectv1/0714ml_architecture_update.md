中端核心架構升級說明文件 (NLP / ML / RAG / LLM)
本文件摘要了中端（NLP/ML分類管線、RAG檢索增強生成、LLM串接）的最新重構重點與運作邏輯，用白話文讓團隊成員快速理解目前的架構優勢。

🚀 核心升級三大步驟白話解析
1. NLP / ML 守門員管線 (ml/build_ml_pipeline.py)
💡 升級前痛點
每次重新訓練模型，都要把全部資料丟給 LLM 重新打標籤（0 或 1），不僅浪費時間，更消耗高昂的 API Token 費用。

當資料量太少時，隨機森林模型會因為「吃不飽」而導致訓練出來的準確度爆掉。

本機 local LLM（如 Qwen）有時候會「碎碎念」，回覆一大串解釋，導致原本設定的嚴格檢查直接把整筆資料丟掉。

🟢 白話調整與現況
我們為管線加上了「智慧省錢防線」與「Regex 翻譯官」：

雙軌打標（融合機制）：現在執行管線時，系統會先去撈取資料庫裡現有的分析結果（例如評分、情緒欄位），自動用規則把標籤打好。只有當現成標籤少於 150 筆（MIN_TRAIN_SAMPLES）時，才會精準計算「還差幾筆」，並只把差額交給 LLM 打標。

Regex 防呆解析：利用正則表達式（Regex），即使 Local LLM 回覆了「這是一篇客訴，所以我給 1」，程式也能像雷達一樣精準抓出裡面的 1，不會再傻傻地把寶貴的資料丟棄。

特徵防噪：在 TfidfVectorizer 中加上 min_df=2，自動排除只出現過一次的錯字或怪異字元組合，讓模型的隨機森林（RandomForest）訓練出來更魯棒。

2. RAG 向量搜尋後台 (Supabase 資料庫)
💡 升級前痛點
資料庫原本只有傳統的文字，沒辦法進行「理解語意」的 AI 向量搜尋。

在 Supabase 寫 SQL 相似度函數時，如果靜態語法裡寫了資料表目前沒有的欄位（例如 rating），資料庫編譯器會直接報錯攔截，導致 RAG 無法運作。

🟢 白話調整與現況
我們在 Supabase 執行了資料庫手術，打通了 RAG 的物理通道：

長出向量翅膀：成功在 master_reviews 資料表注入了 embedding vector(1536) 欄位，未來不論是呼叫 OpenAI 還是 Local Embedding，都有格子可以存文字向量了。

打造超高速比對核心 (match_reviews)：在資料庫內建了一個精簡高效的 RPC 函數。當 Python 端呼叫它時，它會在資料庫底層用向量夾角（Cosine Distance）進行超高速運算，只吐回跟問題最相關的歷史評論內容與相似度分數（similarity）。

完美避開編譯地雷：精簡了回傳欄位，只留下確定存在的 comment_content 與 master_review_id，讓 SQL 順利 Run 成功，同時保持 Python 端傳參的相容性。

3. LLM 與 Prompt 管理 (prompts/ml_prompts.py)
💡 升級前痛點
LLM 的提示詞（Prompt）如果沒有嚴格設限，AI 很容易自我放飛，回傳各種格式（例如：【結果】：0、0. 或是換行）。

🟢 白話調整與現況
我們為 PROMPT_STAGE_1 進行了「軍事化規訓」：

邊界劃清：明確定義什麼叫做「公關危機（標籤 1）」（如髒亂、消費糾紛、態度惡劣），什麼叫做「一般評論（標籤 0）」。

強制閉嘴指令：在 Prompt 尾端加上極具強制力的規範（如：只能輸出一個字元、嚴禁碎碎念、直接輸出結果）。這樣再搭配步驟 1 的 Regex 解析，中端的 LLM 打標防線可謂滴水不漏。




第二階段優化

1. ml/build_ml_pipeline.py 中引入了 Jieba 精準斷詞 與 繁體中文核心停用詞過濾機制：依詞斷句，界線分明：揮別字元盲切，改以「詞」為度量衡。將文本精準解構為 [牛肉湯]、[蒼蠅]、[拉肚子] 等具備實質語意傾向的詞彙實體。澄澈特徵，過濾虛詞：立下字詞之黑名單，凡無關公關危機之虛詞一律削去。使 TfidfVectorizer 能以極其專注的姿態，僅針對具備「情緒價值」與「食安風險」的黃金詞頻進行 $N\text{-gram}$ 矩陣映射。

2.backend/supabase_db.py 內建置了 Hybrid 混合檢索函數 (match_reviews_hybrid)。此技術將傳統之「字面精確匹配」與現代之「AI 語意空間感應」熔鑄於一爐：
橫向死守文字（關鍵字雷達）：死守「牛肉湯」之實體字面，若名相不符，則予以權重懲罰，確保標的之純正。
縱向洞悉心靈（向量空間雷達）：持續發動 1536 維度之向量感應，追尋「客訴、危機」之情感共振。
最終，透過嚴謹的數學公式，將關鍵字匹配分數（ts_rank）與向量餘弦相似度進行黃金比例融合，淬鍊出綜合精準度分數（combined_score）。


第三階段優化
1. 中端智慧大腦樞紐 (backend/ml_analyzer.py): 此檔案為中端大腦之核心。當新評論傳入時，它會發動「語意防護罩」，秒級偵測是否有相似歷史客訴，直接查表複製答案，為老闆省下大筆 AI Token 開銷；若為全新評論，則自動拆解出「憤怒值、失望值、喜悅值」與「危機範疇標籤」，並自動寫入資料庫結果表。

2. 中端專屬前端出菜利刃 (tools/frontend_helper.py): 此檔案是中端主動為前端（Streamlit）開發工程師寫好的「視覺化小幫手」。前端工程師不需要自己寫複雜的資料切片或長條圖邏輯，直接調用這個工具，網頁畫面上就會自動長出華麗的危機紅綠燈與消費者多維情緒長條圖。

3.優化升級版機器學習管線 (ml/build_ml_pipeline.py): 此檔案為中端隨機森林模型之訓練核心。改版後正式引入了台灣慣用的 Jieba 斷詞技術 與 繁體中文核心停用詞白名單，大刀一揮斬斷「的、了、在、我」等無效字元雜訊，讓模型訓練之 Accuracy（準確度）達到純淨、精準的全新境界。



總結:

NLP / ML 訓練管線 (build_ml_pipeline.py)：加入了 Jieba 斷詞、中文停用詞過濾，並優化了雙軌打標與 Regex 解析，大幅提升隨機森林模型的訓練精度與穩定度。

中端智慧分析核心 (ml_analyzer.py)：具備 95% 相似度的語意快取省錢防護罩、3 輪指數退避重試容錯、隨機森林模型動態載入、0.40 黃金危機門檻（寧錯殺、不漏接），以及多維情感（anger/joy/disappointment）與自動標籤拆解。

前端 Streamlit 專屬對接外掛 (frontend_helper.py)：為前端寫好了自動渲染指標與情緒長條圖的元件，前端直接導入即可。

Supabase 資料庫（RAG 檢索增強）：順利在資料庫內新增了向量欄位 embedding，並成功建置與運行了混合檢索函數 match_reviews_hybrid。
