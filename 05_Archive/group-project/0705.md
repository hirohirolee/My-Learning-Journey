### 新增檔案

#### `group-project/prompts/ml_prompts.py`
- 定義常數 `PROMPT_STAGE_1`：Few-shot 二元分類提示詞
- **分類定義**
  - `1` → 實質危機客訴（食安異物、惡劣態度、產品瑕疵、法律威脅）
  - `0` → 無關內容（廢文、純好評、日常閒聊）
- **輸出規範**：只能輸出單一字元 `0` 或 `1`，不得附加任何說明
- **範例設計**：10 組（5 正例 / 5 反例），涵蓋語氣委婉但內容嚴重的邊界案例
  - 邊界正例：「吃完肚子不舒服，懷疑食材沒妥善保存」→ `1`
  - 邊界反例：「湯溫比之前低一點，希望更燙些」→ `0`
- 唯一入參 `{text}`，呼叫方式：`PROMPT_STAGE_1.format(text=input_review)`

## 第二段：ML 訓練管線

### 新增檔案

#### `group-project/build_ml_pipeline.py`（313 行）

**完整流程：**

1. **撈取資料** — 呼叫 `fetch_all_reports()`，過濾空白 `review` 欄位，支援 `MAX_RECORDS` 環境變數限制筆數
2. **LLM 自動打標籤**
   - 批次處理（`BATCH_SIZE`），批次間 `SLEEP_SECONDS` 做速率控制
   - LLM 回傳非 `0`/`1` → 捨棄並 log，管線不中斷
   - 每 50 筆印出進度報告
3. **訓練 ML 模型**
   - `TfidfVectorizer`（`analyzer=char_wb`，字元 n-gram `(2,4)`，適合中文）
   - `train_test_split`（80/20，`stratify=y`）
   - `RandomForestClassifier`（`n_estimators=200`，`class_weight="balanced"`）
   - 印出 Accuracy、Precision、Recall、Confusion Matrix、`classification_report`
4. **匯出模型** — `joblib` 匯出至 `./models/classifier.pkl` 與 `./models/vectorizer.pkl`

**可調環境變數：**

| 變數 | 預設值 | 說明 |
|---|---|---|
| `ENGINE` | `openai` | `openai` 或 `ollama` |
| `MAX_RECORDS` | 不限 | 撈取筆數上限 |
| `BATCH_SIZE` | `10` | 每批 LLM 呼叫數 |
| `SLEEP_SECONDS` | `1.0` | 批次間隔秒數 |

**執行方式：**
```bash
python build_ml_pipeline.py

# 快速測試（Ollama + 限 200 筆）
$env:ENGINE="ollama"; $env:MAX_RECORDS="200"; python build_ml_pipeline.py
```

## 第三段：守門員注入主流程

### 修改檔案：`group-project/api_server.py`

**設計原則：嚴禁碰觸既有 RAG / LLM 核心邏輯，以最小侵入完成注入**

#### 新增函式（3 個，均以 `_` 開頭標示內部使用）

| 函式 | 功能 |
|---|---|
| `_load_ml_gatekeeper()` | 啟動時載入 `.pkl` 模型；失敗 → `(None, None)` 放行，不中斷服務 |
| `_ml_predict_crisis_prob(text)` | 回傳危機機率 `[0.0, 1.0]`；任何異常 → `None`（透明旁路） |
| `_save_gatekeeper_intercept(review, rating, prob)` | 攔截記錄寫 Supabase，動態欄位過濾，失敗僅 log |

#### 新增模組層級語句
```python
ML_GATEKEEPER_THRESHOLD: float = float(os.environ.get("ML_GATEKEEPER_THRESHOLD", "0.7"))
_ml_clf, _ml_vec = _load_ml_gatekeeper()  # 啟動時執行一次
```

#### 注入點（`analyze_review_api` 函式內）
在 `initial_state` 組裝完畢後、`app_workflow.invoke()` **之前**插入：

```
機率 < 門檻 → 攔截，log [ML Gatekeeper] 攔截，寫回 Supabase，提前 return
機率 >= 門檻 → 放行，log [ML Gatekeeper] 放行，繼續走原有 RAG + LLM 流程
模型未就緒  → 透明旁路，全部放行（安全降級）
```

#### 調整門檻方式
```bash
# .env 或環境變數設定後重啟 uvicorn 生效
ML_GATEKEEPER_THRESHOLD=0.7   # 預設，較寬鬆
ML_GATEKEEPER_THRESHOLD=0.5   # 嚴格模式，攔截更多
ML_GATEKEEPER_THRESHOLD=0.85  # 寬鬆模式，幾乎全放行
```

## 學習重點整理

1. **架構設計**：用「透明旁路（Bypass）」模式處理模型未就緒的降級場景，服務不中斷
2. **Few-shot 提示詞工程**：邊界案例比正反典型更重要——語氣委婉但事實嚴重的評論才是分類器最容易出錯的地方
3. **動態欄位過濾**：Supabase 寫入前先 `SELECT * LIMIT 1` 偵測實際欄位，防止 schema 不一致導致插入失敗
4. **速率控制**：批次打標時 `time.sleep()` 放在批次間而非每筆後，在效率與限流之間取得平衡
5. **sklearn 中文文本**：`TfidfVectorizer(analyzer="char_wb", ngram_range=(2,4))` 對中文的效果優於預設的 word-level tokenizer
6. **最小侵入原則**：所有新增函式以 `_` 前綴隔離，注入點只加不改，方便未來 code review 與 rollback
