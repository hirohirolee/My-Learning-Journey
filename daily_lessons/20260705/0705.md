## 第二段：ML 訓練管線

### 新增：`group-project/build_ml_pipeline.py`（313 行）

1. **撈取資料** — `fetch_all_reports()`，支援 `MAX_RECORDS` 限制筆數
2. **LLM 自動打標籤** — 批次 + sleep 速率控制；非 0/1 回傳捨棄並 log；每 50 筆進度報告
3. **訓練 ML 模型**
   - `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,4))` 適合中文
   - `train_test_split(test_size=0.2, stratify=y)`
   - `RandomForestClassifier(n_estimators=200, class_weight="balanced")`
   - 印出 Accuracy、Precision、Recall、Confusion Matrix
4. **匯出** — `joblib` 至 `./models/classifier.pkl` 與 `./models/vectorizer.pkl`

**可調環境變數：**

| 變數 | 預設 | 說明 |
|---|---|---|
| `ENGINE` | `openai` | `openai` 或 `ollama` |
| `MAX_RECORDS` | 不限 | 撈取筆數上限 |
| `BATCH_SIZE` | `10` | 每批 LLM 呼叫數 |
| `SLEEP_SECONDS` | `1.0` | 批次間隔秒數 |

```bash
python build_ml_pipeline.py
# 快速測試
$env:ENGINE="ollama"; $env:MAX_RECORDS="200"; python build_ml_pipeline.py
```

### 修改：`group-project/api_server.py`

**原則：嚴禁修改既有 RAG / LLM 核心邏輯，以最小侵入完成注入**

#### 新增函式（3 個，`_` 前綴標示內部使用）

| 函式 | 功能 |
|---|---|
| `_load_ml_gatekeeper()` | 啟動時載入 `.pkl`；失敗 → `(None, None)` 放行，不中斷服務 |
| `_ml_predict_crisis_prob(text)` | 回傳危機機率 `[0, 1]`；異常 → `None`（透明旁路） |
| `_save_gatekeeper_intercept(review, rating, prob)` | 攔截記錄寫 Supabase，動態欄位過濾，失敗僅 log |

#### 模組層級新增

```python
ML_GATEKEEPER_THRESHOLD: float = float(os.environ.get("ML_GATEKEEPER_THRESHOLD", "0.7"))
_ml_clf, _ml_vec = _load_ml_gatekeeper()
```

#### 注入點：`analyze_review_api` 函式內

在 `initial_state` 組裝後、`app_workflow.invoke()` 之前：

```
機率 < 門檻 → 攔截，log [ML Gatekeeper] 攔截，寫 Supabase，提前 return
機率 >= 門檻 → 放行，log [ML Gatekeeper] 放行，走原 RAG + LLM 流程
模型未就緒  → 透明旁路，全部放行（安全降級）
```

## 學習重點

1. **透明旁路（Bypass）降級** — 模型不存在時自動跳過，服務不中斷
2. **Few-shot 邊界案例** — 語氣委婉但事實嚴重的評論是分類器最易出錯的地方
3. **動態欄位過濾** — `SELECT * LIMIT 1` 先偵測 schema，防止 Supabase 寫入失敗
4. **速率控制設計** — `sleep` 放批次間而非每筆，兼顧效率與限流
5. **sklearn 中文特徵** — `char_wb` n-gram 優於預設 word-level tokenizer
6. **最小侵入原則** — `_` 前綴隔離新函式，注入點只加不改，方便 rollback
