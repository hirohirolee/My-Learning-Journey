## 🔍 2. RAG 檢索優化與查詢重寫（Query Rewriting）
針對本地 ChromaDB 法規及菜單資料的檢索流程進行了大幅度升級：
* **優化 RAG 切片策略（Line-based Chunking）**：
  * 原先使用 `RecursiveCharacterTextSplitter` 進行字元或標點符號的切片。
  * 由於法規條例與菜單屬於結構化/條列式文字，修改為**以行為單位進行精確切片（Line-based）**，避免一條法條被截斷到不同分塊中，確保每一項檢索內容的語意完整性。
* **引入 LLM 查詢重寫**：
  * 當用戶輸入語氣強烈、語義發散的 Google 評論時，直接檢索效果不佳。
  * 新增 `llm_rewriter`（使用 `gpt-4o-mini`），將顧客評論先進行「核心關鍵字/法規主旨提煉」（例如將 "吃牛肉湯發現有一隻蒼蠅！" 重寫為 "食品良好衛生規範準則 衛生問題 異物"），再利用提煉後的關鍵字進行 Chroma 相似度檢索，大幅提升 RAG 法規匹配精準度。

## ⚡ 3. Supabase pgvector 歷史案例檢索與 Few-Shot 機制整合
為了讓 AI 生成的危機公關報告能參考歷史上審核通過的優秀案例，實現 Few-Shot（少樣本）學習：
* **Supabase 表結構與寫入擴充**：
  * 修改 [supabase_db.py](file:///d:/Projects/My-Learning-Journey/group-project/supabase_db.py) 中的 `save_pr_report()` 函數，新增支援 `embedding` 欄位寫入。
  * 在 `cols` 寫入過濾白名單中，加入了 `"embedding"` 和 `"report_content"`，確保每一次產生的評論與報告都能完整保存向量以供日後搜尋。
* **新增 RPC 向量檢索函數**：
  * 在 [supabase_db.py](file:///d:/Projects/My-Learning-Journey/group-project/supabase_db.py) 實作 `search_similar_reviews()`，透過呼叫 Supabase SQL RPC (`match_reviews`) 進行餘弦相似度計算。
  * 檢索時加入 **`filter_rating` 元數據過濾（Metadata Filtering）**，確保系統只會檢索與當前客訴「相同星等（Rating）」的歷史案例，防止將 5 星感謝範本拿去處理 1 星食物中毒危機。
* **主工作流整合 Few-Shot 機制**：
  * 重構了 [app.py](file:///d:/Projects/My-Learning-Journey/group-project/app.py), [api_server.py](file:///d:/Projects/My-Learning-Journey/group-project/api_server.py), 及 [web_app.py](file:///d:/Projects/My-Learning-Journey/group-project/web_app.py)。
  * 當分析進行到 `rag_retriever_node` 時，先呼叫 `OpenAIEmbeddings`（使用 `text-embedding-3-small`）生成查詢向量，從 Supabase 資料庫抓取相似的 2 筆歷史案例（含顧客評論與當時核准的公關報告）。
  * 抓取的歷史案例會被動態格式化並組裝到 Few-shot Context 中，注入回公關生成 Prompt（即 `{few_shot_examples}` 佔位符），讓 LLM（`gpt-4o-mini` 或 `qwen`）能進行情境模仿與相似補償額度的參考。
* **新增原型測試腳本**：
  * 新增 [supabase_rag_prototype.py](file:///d:/Projects/My-Learning-Journey/group-project/supabase_rag_prototype.py) 作為獨立的 RAG 工作流原型，用於快速測試 Supabase Embedding 轉換、RPC 檢索以及 Few-shot 危機報告生成全流程。
